# pg_fts 1.16.0 release record (2026-11-04)

**Current.**  1.16.0 = 1.15.2 + everything on main since it (CHANGELOG 1.16.0):

- **Decode-path fixes found by the CBMC proofs** (95dd408): `wand_load_block` sized no
  FOR column against its block; the same class in the doclen sidecar readers and
  `bm25_decode_term`; five dictionary walks without `bm25_dict_entry_fits`; pointers
  formed past the page from on-disk integers; and a 1-ulp-low BMW bound.
  `bench/RESULTS_CBMC_2026-11-03.md` covers the reproduction, the A/B and the review.
- **`fts_vacuum` drops the tombstones of a single packed segment** (bba830f); this was
  the 1.15.2 known issue.
- **Per-backend tombstone memo** (eca5e75).
- **Collect-path skip for an operand of plain-term readings** (1b3ca35, Codeberg #6).
- **sparsemap 5.8.4** (e58c462).
- **test/cbmc** (95dd408) and its CI drift check.

There are no SQL object changes: `pg_fts--1.15.2--1.16.0.sql` is a no-op. The on-disk
format is unchanged and no REINDEX is needed.

### The upgrade stage

The old side was built from the published v1.15.2 PGXN zip (sha256 `502b0964...`), with
one cluster per major on that build. It held:

- a stored-column index;
- an expression index (sidecar off);
- a partial index;
- tombstones and pending rows.

The 1.16.0 build was then swapped in and `ALTER EXTENSION UPDATE TO '1.16.0'` was run.
Checked results:

- counts equal the heap: stored, expression and partial `count(*)`, the last pushed down;
- the ranked top-20 is unchanged across the upgrade;
- I19a: driven top-20 == the walk;
- the tombstoned top-50 == the walk;
- **the 1.16.0 expunge**: on a single packed segment after a delete and VACUUM,
  `fts_vacuum` returned t, then f; count == heap (21,999); the ranked top-20 equals the
  walk;
- 74 versions reach 1.16.0, none unreachable;
- a fresh install defaults to 1.16.0.

In the per-commit stage every commit is green with no failing tests.  The test count
grows as the tests land: 34 before c465580, which adds `ranked_tombstones` (35), and 36
from 8b407e5, which adds `bmw_block_end`.
