Query forms used
-----------------
CREATE INDEX docs_ps ON docs USING bm25 (id, body) WITH (key_field='id');

rare/mid/common k10/k100 (ranked):
  SELECT id FROM docs WHERE body @@@ 'slovakia' ORDER BY paradedb.score(id) DESC LIMIT 10;
  SELECT id FROM docs WHERE body @@@ 'hungary'  ORDER BY paradedb.score(id) DESC LIMIT 10;
  SELECT id FROM docs WHERE body @@@ 'year'     ORDER BY paradedb.score(id) DESC LIMIT 10;
  SELECT id FROM docs WHERE body @@@ 'year'     ORDER BY paradedb.score(id) DESC LIMIT 100;

count:
  SELECT count(*) FROM docs WHERE body @@@ 'year';

AND (boolean, via tantivy query-string passed straight to @@@):
  SELECT id FROM docs WHERE body @@@ 'slovakia AND hungary' ORDER BY paradedb.score(id) DESC LIMIT 10;

phrase (pg_search's @@@ 'text' form does not accept quoted phrases directly;
used pdb.parse() with a field-qualified Tantivy query string, which does):
  SELECT id FROM docs WHERE body @@@ pdb.parse('body:"united states"') ORDER BY paradedb.score(id) DESC LIMIT 10;

prefix (Tantivy wildcard prefix via pdb.parse()):
  SELECT id FROM docs WHERE body @@@ pdb.parse('body:hung*') ORDER BY paradedb.score(id) DESC LIMIT 10;

All ranked/count/AND/phrase/prefix queries were confirmed to return the
expected row counts before timing (10, 10, 10, 100, 495569, 10 of 3059 total,
10 of 362060 total, 10 of 7535 total respectively).
