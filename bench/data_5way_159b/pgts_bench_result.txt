Index
-----
CREATE EXTENSION pg_textsearch;
CREATE INDEX docs_pgts ON docs USING bm25(content) WITH (text_config='english');

Match counts (df) -- derived via index-scan exhaustion
--------------------------------------------------------
Method: pg_textsearch exposes no df/count function. Ran SET enable_seqscan = off; then
issued the ranked query with LIMIT larger than the true match count, and observed the
row count returned (index scan naturally stops when it runs out of postings, so the
returned row count IS the true match count / document frequency for that term).

slovakia: LIMIT 1000000  -> 10875 matches   (query took 7.568 s -- exhaustion artifact, NOT a latency measurement)
hungary:  LIMIT 1000000  -> 24097 matches   (query took 20.287 s -- exhaustion artifact, NOT a latency measurement)
year:     LIMIT 3000000  -> 734896 matches  (query took 474.545 s / 7m54.545s -- exhaustion artifact, NOT a latency measurement;
                                              this duration is a property of the brute-force full-posting-list scan used only
                                              to derive the match count, not a property of top-k query performance)
