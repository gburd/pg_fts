Index setup
------------
vchord's bm25_ops operator class is FOR TYPE tsvector (not text), so a tsvector column
was materialized before indexing:

  CREATE EXTENSION vchord_bm25 CASCADE;
  ALTER TABLE docs ADD COLUMN tv tsvector;
  UPDATE docs SET tv = to_tsvector('english', coalesce(title,'')||' '||coalesce(body,''));
  VACUUM docs;
  CREATE INDEX docs_vc ON docs USING bm25(tv bm25_ops);
  VACUUM (FREEZE, ANALYZE) docs;

(UPDATE emitted 5x NOTICE "word is too long to be indexed / Words longer than 2047
characters are ignored" — expected tsvector behavior, not an error.)

Build time: 56 s  (CREATE INDEX only, wall clock)
Index size: 2905 MB  (pg_relation_size('docs_vc'))

Operator/function signatures actually installed by this build:
  CREATE TYPE bm25query AS (vector tsvector, index regclass);
  CREATE OPERATOR <&> (PROCEDURE = _bm25_evaluate, LEFTARG = tsvector, RIGHTARG = bm25query);
  CREATE FUNCTION to_bm25query(tsvector, regclass) RETURNS bm25query ...
  CREATE OPERATOR CLASS bm25_ops FOR TYPE tsvector USING bm25 ... OPERATOR 1 <&>(tsvector, bm25query) FOR ORDER BY float_ops;

Ranked query used for all measurements:

  SET "bm25.limit" = <k>;
  SELECT id FROM docs
    ORDER BY tv <&> to_bm25query(to_tsvector('english', '<term>'), 'docs_vc')
    LIMIT <k>;
